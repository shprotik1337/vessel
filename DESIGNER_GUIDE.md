# Руководство UI/UX дизайнера Vessel (DESIGNER_GUIDE)

> **Для кого этот документ:** Для разработчика интерфейсов и его AI-ассистента (нейросети).  
> **Инструкция для нейросети:** Прочитай этот файл перед началом любой работы. Строго соблюдай границы доступа, правила Git и стандарты дизайна.

---

## ⛔ 1. Зона ответственности и жёсткие ограничения

### ✅ ЧТО В ТВОЕЙ ЗОНЕ (Разрешено):
- Всё, что находится внутри папки **`apps/vessel-gui/src/`**:
  - Компоненты (`components/`)
  - Экраны и страницы (`pages/`)
  - Стили и темы (`styles.css`, `customization/`)
  - UI-анимации, модальные окна, поповеры, сетки карточек

### ❌ ЧТО КАТЕГОРИЧЕСКИ ЗАПРЕЩЕНО ТРОГАТЬ (Табу):
- **Rust-ядро:** папка `src/`, файлы `Cargo.toml`, `Cargo.lock`
- **Tauri бэкенд:** папка `apps/vessel-gui/src-tauri/`
- **Аудио-движок и стриминг:** логика плеера, декодеры, буферизация, провайдеры (YouTube, Spotify, SoundCloud, Deezer)
- **База данных и секреты:** SQLite, keyring, токены

> Вся системная логика, воспроизведение и бэкенд находятся на ведущем разработчике. Твоя задача — **чистый, красивый и адаптивный UI**.

## 🌳 2. Правила работы с Git (НИКОГДА НЕ ПУШИТЬ В RELEASE)

Ветка `release` — это релизная ветка для пользователей. Прямой пуш в неё **строго запрещён**.

### Алгоритм работы над любой задачей:

1. **Перед началом работы обнови `release` и создай свою ветку:**
   ```bash
   git checkout release
   git pull origin release
   git checkout -b design/название-задачи
   ```
   *(Например: `design/redesign-playlists`, `design/profile-modal`, `design/wave-tuning`)*

2. **Работай и тестируй ТОЛЬКО в своей ветке:**
   Пиши код, запускай `npm run dev` или `npm run tauri dev`.

3. **Проверь сборку фронтенда перед коммитом:**
   ```bash
   cd apps/vessel-gui
   npm run build
   ```
   Сборка должна проходить **с 0 ошибок TypeScript**!

4. **Закоммить и отправь свою ветку на GitHub:**
   ```bash
   git add apps/vessel-gui/
   git commit -m "design: краткое описание того, что изменил"
   git push -u origin design/название-задачи
   ```

5. **Создай Pull Request:**
   Зайди на [GitHub репозитория](https://github.com/shprotik1337/vessel) и нажми зелёную кнопку **«Compare & pull request»** (в ветку `release`). Ведущий разработчик проверит код и сольёт его сам.

## 🎨 3. Главные визуальные законы интерфейса Vessel

### 1. Дефолтный эталон — чистый AMOLED (#000000)
- Базовый цвет холста, боковой панели, карточек и плеера в дефолтной теме — глубокий чёрный `#000000`.
- Никаких серых засветов на фонах карточек в теме AMOLED.

### 2. Принцип 100% Theme-First (Zero Hardcoded Colors)
**Категорический запрет на жёстко закодированные цвета фона и границ** в коде компонентов (`#121216`, `#18181b`, `rgba(25, 25, 30, ...)`).  
Все элементы (карточки, модалки, поповеры, кнопки, инпуты) обязаны динамически использовать CSS-переменные:
- `var(--app-bg)` — общий фон окна
- `var(--card-bg)` — фон карточек, списков, поповеров и блоков
- `var(--sidebar-bg)` — фон навигационной панели
- `var(--player-bg)` — фон мини-плеера
- `var(--border)` — цвет рамок и разделителей
- `var(--elev)` — полупрозрачная подложка / ховер
- `var(--text)` — основной текст
- `var(--text2)` — второстепенный текст (подписи, авторы)
- `var(--accent)` — акцентный цвет активных кнопок и ползунков
- `var(--accent-contrast-text)` — контрастный цвет текста на акцентной кнопке

*Интерфейс должен безупречно смотреться при переключении на любую тему: AMOLED, Crimson, Nord, Sky или пользовательский пресет.*

### 3. Безопасная зона скролла (Safe Area 180px)
- Внизу окна всегда закреплён плавающий мини-плеер.
- Чтобы плеер не перекрывал нижние карточки, кнопки и текст, область контента обязана иметь нижний отступ:
  ```css
  .content {
    padding-bottom: 180px;
  }
  ```
- При любых изменениях проверяй, что последний ряд контента прокручивается свободно выше плеера.

### 4. Фирменные цвета стриминговых сервисов
Иконки платформ всегда сохраняют свои оригинальные брендовые цвета:
- **Spotify:** `#1DB954`
- **SoundCloud:** `#FF5500`
- **YouTube Music:** `#FF0000`
- **VK:** `#0077FF`
- **Deezer:** `#A238FF`
- **Яндекс Музыка:** `#FFCC00`

Нельзя заливать активные иконки брендов белым или серым цветом.

### 5. Симметрия сеток и интерактивность
- Сетки карточек должны быть аккуратными, без висящих одиноких карточек на новой строке.
- Все кликабельные элементы должны иметь плавный ховер: `transition: all 0.15s ease`.
- Любой поповер или всплывающее меню обязаны закрываться при клике вне их области.
